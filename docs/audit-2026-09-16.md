## Critical (real bugs in normal use)

1. **[services.rs] Registry race → live service becomes unkillable.** The child-wait monitor
   removes registry entries by id only. If an old incarnation's monitor fires *after* a new
   incarnation's `registry().insert(...)`, it wipes the live entry — subsequent Stop is a silent
   no-op (process keeps running, port stays held). Same collision with overlapping start/restart.
   Fix: monitor captures its pgid, removes only when `map.get(&id) == Some(&pgid)`.

2. **[app.rs] False crash notification on every restart.** `RestartService` never inserts into
   `self.stopping`, so the SIGTERM death of the old incarnation trips the crash path
   (`code == None ≠ Some(0)` while `Starting`). Fix: insert into `stopping` before dispatching
   restart (same as StopService does).

3. **[app.rs] Corrupt `services_json` = permanent data loss.** Parse failure silently becomes an
   empty list; the next save overwrites the config with just that list. Fix: distinguish corrupt
   from empty, refuse to persist until user acknowledges.

## Important

- Genuine crash notification can be swallowed if user clicks Stop before the queued Exited event
  arrives (`stopping` boolean set is too coarse — use per-death generation/id).
- Stop during in-flight start: `stop_managed` finds empty registry → returns Ok → process starts
  anyway and shows Running (start/stop not serialized per id).
- Fast-fail commands: `Exited` processed before `StartResult(Ok)` → UI shows "running" forever for
  a dead service (verify registry in StartResult before setting Running).
- `health_all` is sequential — one hung service delays all checks up to 4.5s each. Use `join_all`.
- Scans + health checks run every tick even with the popup closed (2 subprocesses every 2s).
  Gate the tick stream on popup state.
- Logs: unbounded append + `read_tail` does whole-file `fs::read` every 2s (multi-GB log = multi-GB
  read). Seek from end instead; consider rotation cap.
- Log-viewer race: stale `read_tail` can render service A's log in B's view. Tag `LogText` with id.
- `https://` services always show "unhealthy" (raw TCP+HTTP, no TLS). Reject https at save or add TLS.
- Popup content isn't scrollable — long lists clip the footer off-screen. Wrap in `scrollable`.
- Signaling shells out to `kill(1)` with `.unwrap_or(true)` defaults; `libc::kill` removes 4
  subprocesses per stop and gives exact ESRCH/EPERM.
- PID-reuse risk: kill from a stale ports list could hit an unrelated process; verify
  `/proc/<pid>/comm` matches before signaling.
- Two applet instances: config last-writer-wins + duplicate notifications.
- lsof truncates process names at 9 chars — add `+c0`.
- **Zero tests** — parsers (`parse_lsof`, `parse_ss`, `parse_address`, `group_by_process`) are pure
  and table-testable; flagged by all three reviewers.

## Minor

  `[A-Za-z0-9_-]`.
- `child.id().unwrap_or(0)` → pgid 0 would target the applet's own group on stop; return Err.
- `notify-send` missing = notifications silently never appear; probe once.
- `-lc` sources login profiles on every start (slow); `-c` unless env inheritance wanted.
- Open uses `localhost` even for IPv6-only listeners → wrong-URL refusals; use scanned host.
- `Grouped "Open"` opens only the first port of a multi-port process.
- 12-row hard cap with no "+N more" indicator.
- Error banner only clears on successful start; `Health::Failed` details only render while Running.
- `notify-send -a "LooPee"` typo (app name is loPee).
